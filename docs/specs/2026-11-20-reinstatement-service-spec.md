## 1. 目的

HQ Design 新增一項服務：**退租復原工程**。客戶搬離辦公室前，幫客戶把空間還原成房東要求的狀態，順利完成點交、拿回押金。

網站要做到兩件事：

1. 讓對的人看得懂這項服務，並且用真實案例的前後對照建立信任。
2. 表單是 CTA：**第一步只拿聯絡方式**，其他資料讓客人自己選擇要不要補。

### 不在這次範圍（Non-Goals）

- 不做英文頁（之後另做 i18n）。
- 不在網站放價格或每坪單價。
- 不在網站寫現勘是否收費。
- **不做照片／檔案上傳**。上傳需要 Supabase 後台，列為第二階段（見 §10.2）。
- 不用 LINE 收資料。
- 不做線上即時估價。

## 3. 目標客群與使用情境

四種客群都要照顧。第二步第一題「你是誰」用來分流（見 §7）。

### 3.1 公司行政／總務（主要客群）

- **情境**：租約快到期，老闆交代「把舊辦公室處理好」。有死線，不懂工程。
- **擔心**：來不及、押金被扣、跟房東吵架、不知道要拆什麼。
- **要給他的資訊**：流程很簡單、有死線也能排、「不知道要拆什麼沒關係」、我們陪你點交。
- **我們要從他拿到**：先拿聯絡方式；有的話再補地址、到期日、拆除項目。

### 3.2 外商 Facility 主管

- **情境**：總部要求流程透明、要報告、要合規。之後會看英文頁。
- **擔心**：流程不清楚、沒有文件可以交差。
- **要給他的資訊**：清楚的步驟、交付文件（施工前後照片、清運證明、點交紀錄）。
- **我們要從他拿到**：同 3.1，加上多據點資訊。

### 3.3 房東／物業管理

- **情境**：租客要搬走，或租客已經搬走但還原不完整。
- **擔心**：還原品質不好、租客亂拆、施工吵到其他住戶。
- **要給他的資訊**：我們照原樣還、守大樓規定、也可以只做「點交前檢查」。
- **我們要從他拿到**：租客搬離日、需要的是施工還是檢查、原始屋況資料。

### 3.4 搬遷中的公司（舊的要還、新的要裝）

- **情境**：同時處理舊辦公室還原和新辦公室裝修。
- **擔心**：兩頭燒、時程對不上。
- **要給他的資訊**：一個團隊同時處理兩邊，時程一起排。
- **我們要從他拿到**：3.1 的資料 + 新辦公室地址與坪數（選填）。
- **商業意義**：這是導向既有室內設計服務的加購入口。

## 6. 服務頁內容大綱

依序 8 個區塊：

1. **Hero：前後對照**
   - 主視覺：中興保全南港總部 7 樓，「完工時」對照「復原後」的滑桿（左右拖曳比較）。
   - 準備 3～5 組同角度的照片對，可切換。
   - 標題方向：「租約到期前，幫你把辦公室還給房東」
   - 副標：拆除、還原、清運、陪同點交，一次處理
   - CTA：留下聯絡方式 →
   - 照片處理規則見 §6.1
2. **你是不是遇到這些問題**（痛點）
   - 租約快到期，不知道從哪裡開始
   - 不確定哪些要拆、哪些是房東的
   - 擔心押金被扣
   - 大樓只准晚上或假日施工
3. **我們做什麼／不做什麼**
   - 做：拆除隔間與裝修、還原指定項目、廢棄物合法清運、清潔、陪同點交
   - 不動：房東財產（施工前先標記確認）
4. **流程（5 步）**
   留下聯絡方式 → 現場勘查 → 報價與工期 → 施工（配合大樓規範）→ 陪同點交
5. **你需要準備什麼**（有就給，沒有我們幫你找）
   - 現況照片（手機拍即可）
   - 當初承租時的照片或點交紀錄
   - 房東還原清單、租約的還原條款
   - 原始圖面（竣工圖、室裝圖）
   - 大樓施工規範
6. **你會拿到什麼**
   - 施工前後對照照片
   - 廢棄物清運證明
   - 點交紀錄
7. **常見問題 FAQ**（見 §9）
8. **結尾 CTA**：「離租約到期還有多久？先留下聯絡方式，我們會聯絡你。」

### 6.1 前後對照照片處理規則

- 來源：
  - before：`中興保全南港總部｜7樓照片/小檔案網路用`（攝影師完工照，21 張，2000×1333）

## 7. 需求表單規格

### 7.1 原則

- 表單本身就是 CTA。**第 1 步只拿聯絡方式**，送出就算成功留單。
- 第 2 步全部選填，可以整步跳過。
- 每個「不知道」都要有選項，客人不能被卡住。
- 手機優先，有進度條（1／2、2／2）。

### 7.2 第 1 步：聯絡方式（必填）

| 欄位     | name              | 類型  | 必填 | 說明                    |
| -------- | ----------------- | ----- | ---- | ----------------------- |
| 聯絡人   | `name`            | 文字  | 是   |                         |
| 公司名稱 | `company`         | 文字  | 是   |                         |
| 電話     | `phone`           | 電話  | 擇一 | 電話或 Email 至少填一個 |
| Email    | `email`           | Email | 擇一 |                         |
| 個資同意 | `privacy_consent` | 勾選  | 是   | 依個資法告知用途        |

按鈕：「送出，我們會聯絡你 →」。送出後直接進入第 2 步，畫面上方顯示「已收到你的聯絡方式」。

### 7.3 第 2 步：需求資料（全部選填）

畫面開頭：「多告訴我們一點，報價會更快更準。不想填可以直接跳過。」
按鈕兩個：「補充送出」與「先跳過」。

**A. 你是誰**

| 欄位   | name   | 類型 | 說明                                                         |
| ------ | ------ | ---- | ------------------------------------------------------------ |
| 你是誰 | `role` | 單選 | 我是租客，要搬走／我是房東或物管／我要搬家（舊的還、新的裝） |

**B. 場地與時間**

| 欄位                                       | name            | 類型     | 說明                                   |
| ------------------------------------------ | --------------- | -------- | -------------------------------------- |
| 地址與樓層                                 | `site_address`  | 文字     | placeholder：台北市內湖區○○路○號 12 樓 |
| 租約到期日（房東選項顯示為「租客搬離日」） | `lease_end`     | 日期     | 可勾「還不確定」                       |
| 坪數                                       | `area_ping`     | 數字     | 「填大概就好」                         |
| 大樓名稱                                   | `building_name` | 文字     |                                        |
| 再加一個地點                               | `sites[]`       | 重複區塊 | 每個地點：地址樓層、坪數、到期日       |

**C. 拆除項目**

每一項三個選項：**要拆／保留（房東的）／不確定**。最上方總開關：「全部不確定，請現勘時幫我判斷」。

項目：一般隔間牆、玻璃隔間、天花板、地毯／地板、燈具、空調、網路與弱電線路、門禁與監視器、招牌與 Logo 牆、家具與櫃體、水電（茶水間、管線）、其他（文字欄）。

**D. 手上的資料**

| 欄位                 | name             | 類型 | 說明                                                       |
| -------------------- | ---------------- | ---- | ---------------------------------------------------------- |
| 房東有沒有給還原清單 | `landlord_list`  | 單選 | 有／沒有／不知道（重點題）                                 |
| 手上有哪些資料       | `docs_available` | 複選 | 現況照片、承租時照片、租約還原條款、原始圖面、大樓施工規範 |
| 備註                 | `docs_note`      | 文字 | 例如「房東說前門旁的木板隔間要補回」                       |

提示文字：「有這些資料的話，我們聯絡你時會再跟你索取。」（第一階段不提供上傳）

**E. 其他**

| 欄位           | name               | 類型   | 顯示條件      | 說明                               |
| -------------- | ------------------ | ------ | ------------- | ---------------------------------- |
| 房東需要的服務 | `landlord_service` | 單選   | `role` = 房東 | 做還原施工／只做點交前檢查／不確定 |
| 新辦公室地址   | `new_site_address` | 文字   | `role` = 搬家 |                                    |
| 新辦公室坪數   | `new_site_area`    | 數字   | `role` = 搬家 |                                    |
| 方便聯絡的時間 | `contact_time`     | 單選   | 全部          | 上午／下午／都可以                 |
| 其他想說的     | `note`             | 長文字 | 全部          |                                    |

### 7.4 驗證規則

- 第 1 步：`name`、`company`、`privacy_consent` 必填；`phone` 與 `email` 至少一個。
- 第 2 步：不做任何必填檢查。
- `lease_end` 早於今天時，提示「日期已過，確定嗎？」但不擋送出。

### 7.5 兩步如何對在一起

- 進入表單時，前端產生一組參考編號，例如 `RS-20261120-7Q4K`。
- 第 1 步與第 2 步各送出一次，兩次都帶同一個 `ref_id`。
- 內部收到兩封通知時，用 `ref_id` 對起來。客人只填第 1 步也完全沒問題。

## 8. 送出之後

### 8.1 感謝頁

1. 「收到了！我們會盡快聯絡你。」（回覆時效待確認，見 §12）
2. 顯示參考編號 `ref_id`。
3. 「接下來會發生什麼」：電話聯絡 → 安排現勘 → 報價。
4. 「可以先準備的資料」清單（同 §6 第 5 區塊）。
5. 連到服務頁 FAQ。

### 8.2 內部通知

- 第 1 步主旨：`【HQ 退租復原｜新聯絡】{公司名稱}｜{ref_id}`
- 第 2 步主旨：`【HQ 退租復原｜補充資料】{公司名稱}｜{地址}｜到期 {日期}｜{ref_id}`
- 有到期日的依日期排序，**越近越優先**。

### 8.3 內部現勘確認清單（客人通常不會知道，現勘時補齊）

這份清單從真實案件整理而來，不放在客人表單裡：

- [ ] 大樓可施工時段（平日／夜間／假日）
- [ ] 噪音限制
- [ ] 廢棄物能否搬出、暫放位置
- [ ] 卸貨區能否停車、限時
- [ ] 廠商車輛停車位置、地下室限高
- [ ] 房東財產清單（天花板、燈具、冷氣風機、窗簾等）
- [ ] 特殊還原項目（例如防火板隔間要補回）
- [ ] 特殊材質區域（例如採光罩下方有封板，不是只拆輕鋼架）
- [ ] 原始圖面：竣工圖、室裝圖、使照圖（確認範圍與大樣）
- [ ] 多據點時，每個據點分開確認以上項目

## 10. 技術注意事項

### 10.1 第一階段（現在）

- 沿用 Formspree（目前 `contact.html` 使用 `action="https://formspree.io/f/..."`）。兩步各送一次，用 `ref_id` 串接。
- 第 1 步送出要用 JavaScript（fetch）送，送完留在頁面進入第 2 步；不支援 JavaScript 時，退化成一般表單送出並導向感謝頁。
- 多據點欄位命名要在 Email 中讀得懂（例如 `site_2_address`）。
- 個資同意文字需與既有網站隱私說明一致。
- 中文頁 `lang="zh-TW"`；之後英文頁加 `hreflang` 互相對應。
- 前後對照滑桿：純 HTML／CSS／少量 JavaScript，支援觸控拖曳與鍵盤（左右鍵），圖片用 WebP 並指定寬高避免版面跳動。

### 10.2 第二階段（照片上傳，暫不開發）

- 需要建立 Supabase 後台（資料表 + Storage）。
